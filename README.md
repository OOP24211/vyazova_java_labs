# Примеры реализации Worker Pool в Java

Здесь представлено несколько способов реализации worker pool и асинхронного выполнения задач в Java.

---

# Что такое Worker Pool

Worker pool — это модель многопоточности, где:

- существует очередь задач;
- фиксированное число потоков (workers);
- каждый поток берёт задачу из очереди и выполняет её.

### Зачем это нужно:

- не создавать поток под каждую задачу;
- переиспользовать потоки;
- контролировать нагрузку.

---

# Реализованные варианты

## 1. Ручная реализация (Thread + BlockingQueue)

📄 `ThreadBlockingQueue.java`

### Используемые механизмы:

- `Thread`
- `BlockingQueue<Runnable>`
- `Runnable`
- `interrupt()`

### Как работает:

- создаётся очередь задач;
- создаются worker threads;
- каждый поток в бесконечном цикле ждёт задачу через `queue.take()`;
- после получения задачи выполняется `task.run()`.

### Особенности:

- полный контроль над потоками;
- вручную реализован `shutdown()` через `interrupt()`;
- видно “внутренности” worker pool.

### Что демонстрирует:

- как работает очередь задач;
- как потоки конкурируют за задачи;
- как реализуется остановка потоков.

---

## 2. ExecutorService (готовый thread pool)

📄 `ExecutorServiceExample.java`

### Используемые механизмы:

- `ExecutorService`
- `Executors.newFixedThreadPool()`
- `submit()`

### Как работает:

- Java сама создаёт очередь задач;
- сама управляет потоками;
- задачи распределяются между worker threads.

### Особенности:

- минимальный ручной код;
- встроенный lifecycle управления потоками;
- промышленный стандарт.

### Что демонстрирует:

- стандартный thread pool в Java;
- автоматическое распределение задач;
- переиспользование потоков.

---

## 3. CompletableFuture (асинхронный подход)

📄 `CompletableFutureThread.java`

### Используемые механизмы:

- `CompletableFuture`
- `runAsync()`
- `ExecutorService`

### Как работает:

- задачи выполняются асинхронно;
- используются потоки из thread pool;
- можно строить цепочки обработки результатов.

### Особенности:

- современный async-подход;
- поддержка цепочек `thenApply`, `thenAccept`;
- используется в backend-системах.

### Что демонстрирует:

- асинхронное выполнение задач;
- взаимодействие CompletableFuture и thread pool;
- неблокирующую модель выполнения.

---

# Что делают задачи в примерах

Каждая задача:

- выполняет вычисления (CPU load);
- имитирует работу через `sleep`;
- выводит имя потока, который её выполнил.

Это позволяет увидеть:

- распределение задач между потоками;
- переиспользование worker threads;
- параллельное выполнение.
